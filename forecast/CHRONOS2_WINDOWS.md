# تشغيل Chronos-2 على Windows (F3)

> **الهدف:** تشغيل نموذج Chronos-2 على أسابيع الاختيار الـ14 نفسها، ثم إرسال ملفين صغيرين. الحساب والمقارنة يتمان بعد ذلك بالكود نفسه الذي قيّم النموذجين الآخرين.
> **لا يلمس:** بروتوكول التقييم، والاختبار النهائي (السكربت لا يعرف إلا أسابيع الاختيار)، وDjango.
> الإعداد المثبّت في `forecast/CHRONOS2_SPEC.md`.

**التشبيه:** نستعير طاهيًا محترفًا جاهزًا (نموذج مدرَّب مسبقًا على آلاف السلاسل الزمنية)، ونعطيه المكونات نفسها التي أعطيناها للطاهيين الآخرين. لا ندرّبه ولا نغيّر وصفته، ونقارن الأطباق بالمعيار نفسه.

## 0. الخطوات باختصار

| # | الخطوة | الأمر | تقدير الوقت |
|---|---|---|---|
| 1 | تحديث المستودع | `git pull` من الـbundle | دقيقة |
| 2 | بيئة منفصلة وتثبيت | `pip install -r requirements-chronos.txt` | يعتمد على سرعة الإنترنت (التنزيل قرابة 125 MB لـtorch وحده) |
| 3 | فحص الجاهزية | `python forecast/chronos_preflight.py` | أقل من دقيقة |
| 4 | الاختبارات | `python -m unittest discover -s forecast/tests` | ثوانٍ |
| 5 | التشغيل | `python forecast/run_chronos_local.py` | تنزيل 478 MB أول مرة، ثم التشغيل |
| 6 | الإرسال | ملفان من `forecast\out\f3\chronos2\` | — |

لم أقس زمن التشغيل بالأوزان الحقيقية، لأن بيئتي لا تصل إلى Hugging Face. السكربت يسجّل الزمن الفعلي لكل أسبوع في `run_manifest.json`.

## 1. متطلبات الجهاز

| البند | المطلوب | المصدر أو السبب |
|---|---|---|
| النظام | Windows 10 أو 11، بنسخة 64-bit | torch لا يوفر نسخة 32-bit |
| Python | من 3.10 إلى 3.13، بنسخة 64-bit. نسختك 3.13 مناسبة | `chronos-forecasting` يتطلب ≥3.10، وtorch 2.14.1 فيه ملف جاهز لـ3.13 على Windows |
| معالج الرسوم (GPU) | **غير مطلوب**. يعمل على المعالج (CPU) | صفحة النموذج: يدعم CPU. وtorch على Windows من PyPI نسخة CPU أصلًا |
| الذاكرة (RAM) | 8 GB مريحة | الأوزان وحدها 478 MB بدقة float32، ومعها torch. الحد الأدنى الدقيق لم أقسه |
| المساحة | **3 GB فارغة على الأقل** | النموذج 478 MB، وملف torch قرابة 125 MB قبل فك الضغط. حجم البيئة بعد التثبيت على Windows لم أقسه، والـ3 GB هامش أمان |
| الشبكة | الوصول إلى `pypi.org` و`huggingface.co` | للتثبيت ولتنزيل النموذج مرة واحدة. بعدها يعمل دون إنترنت |

**حجم النموذج:**
- `amazon/chronos-2`: نموذج 120 مليون معامل. الملف `model.safetensors` حجمه 478 MB، ومعه `config.json` (1 KB).
- يُحفظ في `%USERPROFILE%\.cache\huggingface\hub`. لنقله إلى قرص آخر: `$env:HF_HOME = "D:\hf"` قبل التشغيل.

## 2. البيئة والتثبيت

في PowerShell:

```powershell
cd C:\Nouf\Pure_Projects\covercast
git pull "$HOME\Downloads\covercast-update.bundle" main

py -3.13 -m venv .venv-chronos
.venv-chronos\Scripts\activate
python -m pip install --upgrade pip
pip install -r requirements-chronos.txt
```

- **بيئة منفصلة عن `.venv` الخاصة بـDjango:** Django لا يحتاج torch، ولا نريد أن يكبر تثبيته. المجلد `.venv-chronos` متجاهَل في git.
- **إن رُفض أمر `activate`** بسبب سياسة التنفيذ، فشغّلي `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` ثم أعيدي الأمر. هذا يؤثر على هذه النافذة فقط.
- **النسخ المثبّتة:** `chronos-forecasting==2.3.2` و`torch==2.14.1` و`transformers==5.19.0`. لا ترفعيها، حتى تطابق الإعداد.

## 3. فحص الجاهزية (لا يُنزّل شيئًا)

```powershell
python forecast/chronos_preflight.py
```

**المتوقع في آخر سطر:** `READY: 0 fail …`.

ما يفحصه:
- نسخة Python.
- المكتبات ونسخها.
- **أن واجهة Chronos-2 تعمل فعلًا على جهازك:** يبني نموذجًا عشوائيًا صغيرًا في الذاكرة، ويستدعي الدالة نفسها التي سيستدعيها التشغيل الحقيقي.
- المساحة والذاكرة.
- الوصول إلى Hugging Face.

`WARN` تحذير لا يمنع التشغيل، و`FAIL` يحتاج معالجة (القسم 6).

## 4. الاختبارات

```powershell
python -m unittest discover -s forecast/tests
```

**المتوقع:** `Ran 111 tests … OK`، بلا تخطٍّ (كان 81 في F3، ثم أُضيفت اختبارات التجميد في F4).

في هذه البيئة يعمل أيضًا اختبار «المكتبة الحقيقية»: يحفظ نموذجًا عشوائيًا صغيرًا في مجلد، ثم يشغّل السكربت عليه كاملًا. وهذا يجرّب مسار التنزيل اليدوي قبل أن تحتاجيه.

## 5. التشغيل

```powershell
python forecast/run_chronos_local.py
```

**ما سيظهر:**

```text
1/4 model: locating weights (first time downloads about 478 MB) ...
2/4 model: loading on CPU ...
3/4 running 14 selection folds (determinism check first) ...
4/4 done: 98 rows -> ...\forecast\out\f3\chronos2
```

**ما يفعله السكربت، بالترتيب:**
1. ينزّل الإصدار المثبّت من Hugging Face، أو يستخدمه من الذاكرة المؤقتة إن نُزّل سابقًا.
2. **يتحقق من بصمة الأوزان (SHA256).** إن اختلفت عن المثبّتة في الإعداد، يتوقف قبل أي تنبؤ.
3. **يشغّل أول أسبوع مرتين**، ويتوقف إن اختلفت النتيجتان.
4. يشغّل الأسابيع الـ14. في كل أسبوع لا يرى النموذج إلا الحضور حتى يوم الانطلاق.
5. يكتب ملفين: التنبؤات، وسجل التشغيل (النسخ، والبصمات، والأزمنة).

**طريق التنزيل اليدوي**، إن فشل التنزيل الآلي:
1. افتحي في المتصفح: `https://huggingface.co/amazon/chronos-2/tree/29ec3766d36d6f73f0696f85560a422f50e8498c`
2. نزّلي `config.json` و`model.safetensors` إلى مجلد مثل `C:\models\chronos-2`.
3. شغّلي:
   ```powershell
   python forecast/run_chronos_local.py --model-path C:\models\chronos-2
   ```
   البصمة تُفحص هنا أيضًا، فلن يُقبل ملف ناقص أو مختلف.

## 6. إن تعذّر شيء

| ما يظهر | السبب المرجح | ما تفعلينه |
|---|---|---|
| `No matching distribution found for torch` | Python بنسخة 32-bit، أو نسخة غير مدعومة | ثبّتي Python 3.13 بنسخة 64-bit من python.org، ثم أعيدي القسم 2 |
| أخطاء SSL أو proxy أثناء `pip install` | شبكة عمل تحجب أو تفحص الاتصال | جرّبي شبكة أخرى، كالمنزل أو الجوال |
| فشل أو توقف أثناء تنزيل النموذج (Timeout، أو 403، أو SSL) | الشبكة أو جدار الحماية | أعيدي المحاولة مرة بعد `$env:HF_HUB_DOWNLOAD_TIMEOUT = "120"`. إن فشل مجددًا فاستخدمي طريق التنزيل اليدوي (القسم 5) |
| `Revision ... not found` | الإصدار المثبّت لم يعد متاحًا | **توقفي وأرسلي الرسالة.** لا تشغّليه على `main`، لأن ذلك يغيّر الإعداد |
| `model.safetensors is not the file the spec pins` | تنزيل ناقص أو ملف آخر | احذفي الملف، أو مجلد `models--amazon--chronos-2` من الذاكرة المؤقتة، وأعيدي التنزيل. إن تكرر فأرسلي الرسالة |
| `MemoryError`، أو الجهاز يتجمد | ذاكرة غير كافية | أغلقي البرامج الأخرى، وأعيدي التشغيل |
| `two runs of the same fold differ` | نتائج غير قابلة للإعادة | أرسلي المخرجات كاملة، ولا تعيدي المحاولة |
| فشل فحص الواجهة في `chronos_preflight` | تعارض في النسخ | أرسلي مخرجات الفحص كاملة. المشكلة في النسخ لا في التنزيل |

**إن تعذّر التشغيل نهائيًا**، فسجّلي السبب بجملة واضحة:

```powershell
python forecast/run_chronos_local.py --record-unavailable "تنزيل النموذج محجوب على شبكتي بعد محاولتين، والتنزيل اليدوي فشل أيضًا"
```

ثم أرسلي `forecast\out\f3\chronos2\chronos2_unavailable.json`. لا تحتاج هذه الخطوة torch.
- F4 تكمل بالنموذجين، وتُعلن المقارنة **غير مكتملة** في التقرير وفي `selection.json` (F-D6).
- لا تُعرض نتيجة جزئية لـChronos-2 على أنها مقارنة كاملة.

## 7. ما ترسلينه

من `forecast\out\f3\chronos2\`، أرفقيهما في المحادثة كما هما دون تعديل:
- `chronos2_predictions.csv` (98 صفًا: p10 وp50 وp90 لكل يوم، **بلا مقاييس**)
- `run_manifest.json`

أو `chronos2_unavailable.json` وحده، إن تعذّر التشغيل.

**بعد استلامها، أشغّل:**

```bash
python forecast/evaluate.py --stage f3
```

هذا الأمر يرفض الملفات في هذه الحالات:
- صفوف ناقصة، أو صفوف من خارج أسابيع الاختيار.
- تواريخ لا تساوي يوم الانطلاق + الأفق.
- كميات بترتيب خاطئ.
- سلسلة غير `osaka_daily.csv`.
- إصدار إعداد آخر.

ثم يحسب المقاييس الأربعة بالكود نفسه، ويطبّق قاعدة الاختيار المكتوبة مسبقًا على النماذج الثلاثة. ولا أنتقل إلى F4 قبل مراجعتك.

## 8. خصوصية وأمان

- **البيانات لا تغادر جهازك:** السلسلة رسمية ومنشورة، والنموذج يعمل محليًا.
- **الاتصال الوحيد** بـ`huggingface.co`، مرة واحدة لتنزيل الأوزان.
- **لا أسرار ولا حسابات مطلوبة:** النموذج عام بترخيص Apache-2.0، ولا يحتاج تسجيل دخول.

## 9. التشغيل النهائي (F4c) — **لا يُشغَّل إلا بعد موافقة نوف الصريحة**

التجميد موجود (`forecast/out/selection_frozen.json`، commit `f77c24f`)، لكن تفويض F4c لم يُعطَ بعد. حين يُعطى:

```powershell
git pull "$HOME\Downloads\covercast-update.bundle" main
.venv-chronos\Scripts\activate
python forecast/freeze.py --check                  # يجب: OK: freeze holds … sha256 20d80998…
python -m unittest discover -s forecast/tests      # يجب: Ran 111 tests … OK
python forecast/run_chronos_local.py --final
```

**ما يحدث:**
1. السكربت يتحقق من التجميد **قبل** قراءة أي بيانات. إن تغيّر بايت في ملف مثبّت (كود، أو بيانات، أو بروتوكول، أو نتائج F3) يرفض العمل.
2. يسجّل رقم commit المستودع وحالته. لذلك يجب أن يكون git مثبتًا، وأن يُشغَّل من مجلد المستودع.
3. يشغّل الطيّات النهائية الأربع (28 يومًا) بالإعداد نفسه `chronos2-spec-v1`. تنبؤات فقط، بلا قيم فعلية ولا مقاييس.
4. يكتب الملفين في `forecast\out\final\chronos2\`، وتُرسلان كما هما.

**ملاحظات:**
- **فرق نهايات الأسطر في Windows (CRLF) لا يكسر التجميد،** لأن البصمات تُحسب بعد توحيدها. وتعديل ملفات غير مثبّتة، كالوثائق، لا يؤثر.
- **إن تعذّر التشغيل:** `python forecast/run_chronos_local.py --final --record-unavailable "السبب"`، وهو أيضًا يتطلب تجميدًا صالحًا.
