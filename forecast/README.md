# forecast/ — خط التنبؤ بالحضور (خارج Django)

هذا المجلد مستقل عن تطبيق Django، ولا يُستورد منه ([ADR 0009](../docs/adr/0009-forecast-outside-django.md)). الخطة والقرارات في `docs/18-forecast.md`.

**الحالة:**
- F1 (السلسلة الرسمية) وF2 (النموذجان والتقييم) معتمدتان.
- F3 (Chronos-2): شُغّل على جهاز نوف وقُيّم (`out/f3/`).
- F4a/F4b: الاختيار مجمّد في `out/selection_frozen.json` (`seasonal_naive`، `fallback_model`).
- F4c: التقييم النهائي شُغّل مرة واحدة على جهاز نوف (`out/final/`، تقرير فقط). الأدق رقميًا Chronos-2، والمختار يبقى `seasonal_naive` (`docs/18-forecast.md` §9).
- P0: `export_forecast.py` يصدّر إعادة عرض أوساكا لـDjango (`out/export/osaka_replay.json`).

## التشغيل

بيئة منفصلة عن بيئة Django، لأن Django لا يحتاج هذه المكتبات:

```bash
python -m venv .venv-forecast
.venv-forecast\Scripts\activate            # Linux: source .venv-forecast/bin/activate
pip install -r requirements-forecast.txt     # numpy وscikit-learn بنسخ مثبتة

python forecast/build_series.py --check      # F1: السلسلة مطابقة للملفات الخام
python forecast/evaluate.py --check          # F2: النتائج المحفوظة تُعاد حرفيًا
python forecast/evaluate.py                  # F2: إعادة الحساب والكتابة إلى out/f2/
python forecast/evaluate.py --stage f3 --check   # F3: النماذج الثلاثة تُعاد حرفيًا
python forecast/explore_f3.py --check            # F3: التفصيل الاستكشافي (تقرير فقط)
python forecast/freeze.py --check                # F4b: التجميد صالح (بصمات المنطق والبيانات ونتائج F2/F3)
python forecast/evaluate.py --final --check       # F4c: التقييم النهائي يُعاد حرفيًا (لا يشغّل Chronos-2)
python forecast/export_forecast.py --check        # P0: ملف إعادة العرض يُعاد حرفيًا
python -m unittest discover -s forecast/tests -v   # 121 اختبارًا (2 متخطاة بلا chronos)
```

`python forecast/evaluate.py --final` يرفض العمل (رمز الخروج 2) بلا تجميد صالح. وبعد F4c لا يُشغَّل إلا مع `--check`.

## كيف وصلت الأرقام، ولماذا نثق بها

بيئة العمل السحابية لا تصل إلى موقع المعرض من سطر الأوامر، لأن وسيط الشبكة يرفض الاتصال (403). لذلك قُرئت الصفحات بأداة قراءة الويب، ونُسخت الأرقام إلى `raw/`. ويُذكر هذا في عمود `transcription = web_reader_copy`.

خطأ النسخ هو الخطر الحقيقي هنا، فالفحوص مبنية لالتقاطه:

1. **داخل كل خبر:** مجموع الأيام = 合計 المطبوع، للإجمالي ولـAD كلٍّ على حدة. ويوم الأسبوع المطبوع = يوم الأسبوع الحقيقي للتاريخ. والصفوف أيام متتالية تطابق عنوان الفترة.
2. **بين الأخبار:** 累計 المطبوع في كل خبر = 累計 الخبر السابق + 合計 هذا الخبر. هذا يربط الأخبار الستة والعشرين في سلسلة واحدة، فلو أخطأ النسخ في رقم يوم وفي 合計 أسبوعه معًا، انكسرت السلسلة في الخبر التالي.
3. **في النهاية:** 184 يومًا بلا نقص ولا زيادة، والمجاميع = الأرقام النهائية الرسمية.
4. **حقائق مستقلة لم تُستخدم في البناء:**
   - صفحة `expo_data`: «34 يومًا متتاليًا فوق 200 ألف ابتداءً من 10 سبتمبر» تطابق السلسلة (على الإجمالي `visitors_total`).
   - الأيام الأربعة الرسمية في ورقة محمد تطابق، ثلاثة منها مقرّبة في الورقة.

نجحت كل الفحوص من أول بناء. وكل فحص جُرّب بالتخريب: عُطّل في الكود، فالتقطه اختبار.

## ملاحظات أمانة

- **أسماء العطلات:** التواريخ من ملف مجلس الوزراء CSV. لكن النص الياباني فيه وصل مشوّهًا (ترميز Shift-JIS)، فكُتبت الأسماء من قائمة العطلات الرسمية في قانون العطلات الياباني. الأسماء للقراءة فقط، والنماذج تستخدم التاريخ ونوع اليوم (`holiday` أو `substitute`).
- **المصدر الثانوي (futureearth.jp) لم يُستخدم.** السلسلة الرسمية مكتملة، فلا حاجة له (F-D5).
- **الخبر الأخير** (`news-20251014-01`) يغطي 9 أيام (5–13 أكتوبر)، لأن المعرض أُغلق يوم الاثنين. والموقع يعرضه بتاريخ «最終更新 2025.10.23» وعنوان «【更新】». أُخذت الأرقام كما هي يوم الاسترجاع.
- **أيام المشاركين الوطنية:** لم تُضف. ورقة الفريق `national_days` (158 صفًا في `CoverCast_datasets.xlsx`) تذكر رابطًا واحدًا عامًا لكل صفوفها، ولم يُتحقق منها يومًا بيوم (`docs/20-data-provenance.md`).

## Feature Engineering بلغة بسيطة (F2)

التشبيه: نتنبأ بزحام مطعم الأسبوع القادم. نعرف مسبقًا أي يوم هو، وهل هو عطلة، وكم مضى على الافتتاح. ولا نعرف الطقس، ولا كم حجزًا سيأتي. فلا نستخدم إلا ما نعرفه مسبقًا.

| المتغير | ما هو | لماذا | مثال من البيانات |
|---|---|---|---|
| يوم الأسبوع (6 أعمدة ثنائية، والأساس الاثنين) | 1 في عمود يوم ذلك التاريخ، و0 في البقية | أقوى نمط في الحضور | متوسط السبت 157,718، والثلاثاء 125,089 (F1) |
| `holiday` | 1 إن كان عطلة رسمية أو بديلة | العطلة ترفع الحضور، ومعروفة بالقانون مسبقًا | 10 عطل داخل المعرض |
| `t` | رقم اليوم منذ الافتتاح | اتجاه محلي: هل الحضور يصعد أو يهبط هذه الأسابيع | — |

- **لماذا `ln(y)` لا `y`:** أثر السبت نسبة (متوسطه أعلى من الاثنين بقرابة 18% في F1)، لا عدد ثابت. في اللوغاريتم تصير النسبة جمعًا، فيفهمها الانحدار الخطي.
- **لماذا آخر 56 يومًا فقط:** حضور أبريل نصف حضور سبتمبر. الاتجاه المحسوب على كل التاريخ سيقوده الماضي البعيد.
- **ما لم يدخل، ولماذا:**
  - أيام المشاركين الوطنية: بقرار نوف، حتى يُتحقق من مصدرها وتوفرها.
  - أوبون والعطل المدرسية: لا تاريخ رسمي موحد لها في مصادرنا.
  - الطقس والتذاكر: غير معروفة وقت التنبؤ.

## كيف تُحسب المقاييس (F2)

لكل يوم مُقيَّم لدينا الفعلي `y` والتوقع `p50` والفترة `p10–p90`:
- **MAE:** متوسط |y − p50|، بالزوار.
- **WAPE:** مجموع |y − p50| ÷ مجموع y. يُحسب على كل الأيام معًا، لا متوسطًا للطيّات، حتى لا يأخذ أسبوع خفيف وزنًا أكبر من حجمه. **هو وحده معيار الاختيار.**
- **Bias:** مجموع (p50 − y) ÷ مجموع y. السالب يعني أن النموذج يقدّر أقل من الواقع.
- **PI80 coverage:** نسبة الأيام التي وقع فيها الفعلي بين p10 وp90. المثالي 80%.
- **دقة المستوى:** نسبة الأيام التي طابق فيها مستوى p50 (عادي، أو مرتفع، أو ذروة) مستوى الفعلي. والحدود من بيانات ما قبل نقطة الانطلاق فقط.
