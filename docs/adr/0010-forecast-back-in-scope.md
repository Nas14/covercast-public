# ADR 0010 — D2-R: التنبؤ بالحضور يعود إلى الـMVP

**الحالة:** معتمد من نوف (14 أكتوبر 2026). يلغي المختار في ADR 0002، ويُبقي ما بُني بموجبه.

- **السياق:** ADR 0002 أخرج التنبؤ من الـMVP، وأبقى الواجهات فقط (الجدولان، والحقل `volume_uplift`). نوف أوضحت أن ذلك القرار «غير معتمد منها»، وطلبت المكوّن كاملًا: البيانات، ومقارنة النماذج، والتصدير، والاستيراد، والواجهة، والوثائق.
- **المختار:** بناء المكوّن على مراحل F1–F6، كل مرحلة تنتظر الموافقة قبل التالية، وفق الخطة المنشورة «خطة التنبؤ بالحضور» وهذه القرارات:

| الرمز | قرار نوف |
|---|---|
| F-D1 + F-D2 | **مساران للعرض:** (1) Historical Replay لأوساكا 2025 يقارن التوقع بالفعلي. (2) سيناريو تشغيلي مستقل للرياض 2030، موسوم Simulated Scenario، يُظهر أثر مستويات الضغط على `DemandRule` والفجوات والترشيح. لا تُعرض توقعات أوساكا على أنها للرياض، ولا يتغير سيناريو G1/G2 الأصلي. |
| F-D3 | P75 وP90 مبدئيًا، من بيانات التدريب السابقة فقط، مع اختبار حساسية، وتوثيقها حدودًا تجريبية. |
| F-D4 | قيم `DemandRule` تُقترح بعد F4، ولا تُعتمد قبل مراجعة نوف. |
| F-D5 | المصدر الثانوي مقبول بشرط: يُوثَّق ويُوسَم، ولا يُعامل كبيانات رسمية. |
| F-D6 | Chronos-2 يُجرَّب على جهاز نوف، ولا تتوقف عليه المراحل الأخرى. |
| F1b | لا بيانات دبي حاليًا. الأولوية لأوساكا الرسمية. |

- **شروط نوف قبل التنفيذ** (معالجتها في `docs/18-forecast.md`، القسم 3):
  1. أثر الفعاليات لا يُهمل عند غياب التنبؤ، ويبقى منع الاحتساب المزدوج.
  2. فصل صريح بين بيانات أوساكا الرسمية وسيناريو الرياض المحاكى.
  3. لا تسرب من الاختبار النهائي إلى اختيار النموذج أو حدود المستويات، مع توثيق تاريخ إنشاء كل توقع وأفقه.
- **العواقب:** قيد README رقم 3 («لا أمر لاستيراد التنبؤ») يبقى صحيحًا حتى F5، ثم يُحدّث.
